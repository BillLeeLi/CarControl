# 实车核心参数调试指南

依据 `config/baseline.yaml` 和当前控制实现整理，数值记录于 2026-10-23。本文列出优先调试项；其余参数先保留，完整清单见 [README.md](README.md#主要参数)。迁移与首次编译见 [MIGRATION.md](MIGRATION.md)。

**以下“当前值”来自 YAML，并不表示已经完成实车标定。** 当前 YAML 的 `steer_kp=3000.0`，Python 内置默认值仍为 `300.0`；使用本包 launch 会加载 YAML，直接运行且不传参数文件则使用内置值。本文不修改这些数值。

## 1. 现场按什么顺序调

1. **核对坐标和反馈**：雷达前方是否正确；人工前移/转动车辆时，里程计距离、方向是否合理。
2. **标定控制接口**：停止动力、中位、转向正负、前进正负和允许幅度。
3. **低速直行调速度**：`control_mode: closed_loop`、`reference_mode: straight`、`turn_enabled: false`，目标速度可先设 `0.10` m/s。该模式只选合格的车头 0°候选，不保持全局航向，不用于调走廊回中。
4. **调直路巡航**：改回 `reference_mode: corridor`，保留 `turn_enabled: false`，初次标定也可设 `recovery_enabled: false`，便于单独观察正常控制。先确认墙线/中线正确，再调 PD 和回中参考。
5. **单独调右转**：直路稳定后再设 `turn_enabled: true`，核对半径、响应和出口对齐。当前尚未实现左转、短 Z 衔接、S 弯和终点判断，调参不能补齐这些行为。

每次只改一个主要因素；同一路段、相近电量重复观察，记下改前/改后的值与效果。按课程要求在地面空旷处准备，保持手动模式核对后再切自动，必要时立即接管。

## 2. 控制中位、符号与限幅：先确定这些

`steer` 和 `speed` 都是发送到底层的整数控制量；它们不是车轮角度和 m/s。

| 参数 | 当前值 | 含义及现场调整 |
|---|---:|---|
| `steer_center` | 0 | 方向误差为零时的直行中位。用 straight 模式低速检查车轮/行驶是否偏向一侧，小幅调整中位直到接近直行；先排除地面坡度与机械问题。中位不能代替走廊航向纠偏。 |
| `steer_sign` | -1 | 正方向误差（目标在左）映射到底层的符号，只能是 ±1。已获准的左目标却导致向右时，核对雷达坐标后调整此项；不要用负的 `steer_kp` 修正。 |
| `steer_limit` | 600 | 相对中位的最大偏移；输出范围为 `center ± limit`。依实际允许范围确定，不因转弯不足就直接加大。 |
| `stop_speed` | 0 | 停止时发送的动力控制值，需确认实际效果。当前停车还会把转向回到中位。 |
| `speed_sign` | -1 | 正前进动力映射到底层的符号，只能是 ±1。获准前进却倒车时，检查此项。 |
| `speed_effort_limit` | 120.0 | 前进动力幅度上限，实际输出为 `stop_speed + speed_sign × 幅度`。先用设备允许的保守上限；持续顶到上限仍达不到目标速度时，排查电量/负载和目标后再调整。 |

**没有青色目标，或状态正在要求停车时，先查状态原因。** 此时增加增益不能让控制获准。中位和符号测试也需要有效传感器、里程计及可通行方向。

## 3. 速度：先前馈，再 P，最后 I

控制器先让内部目标速度平滑靠近请求值，再计算：

```text
速度误差 = 内部目标速度 - 关联的里程计速度
动力幅度 = 前馈偏置 + 前馈系数 × 内部目标速度 + P项 + I项
```

幅度经限幅和变化率限制后才发布，最低为 0；当前不会自动输出倒车动力制动。

| 参数 | 当前值 | 如何调整 |
|---|---:|---|
| `target_speed_mps` | 0.20 | 全局物理速度请求。首次可降到 0.10；直路稳定后逐步提高。设 0 立即请求停止。降级走廊和转弯可能进一步降低请求。 |
| `max_target_speed_mps` | 0.50 | 接口接受的速度上界，超过会拒绝配置/参考；不是提高实际速度的调节旋钮。 |
| `speed_feedforward_gain` | 200.0 | 目标速度对应的基础动力。多个低速点都需要较多正 P/I 才跟上时，可适当增大；普遍超速则减小。用实车稳态记录估计动力随速度的斜率。 |
| `speed_feedforward_offset` | 0.0 | 正速度请求时附加的基础动力，用于已测出的启动/低速死区。确认有获准前进命令但动力不足以起步后小步增加；过大可能使低速起步突然。 |
| `speed_kp` | 100.0 | 对当前速度误差的响应。跟速慢且没有限幅/限速时可增加约 10–20%；速度反复冲高再回落则减小。 |
| `speed_ki` | 30.0 | 消除长期速度偏差。前馈和 P 基本合适后，仍稳定偏慢再小步增加；慢周期忽快忽慢、超调明显时减小。 |
| `speed_integral_limit` | 30.0 | **已乘 Ki 的积分项**最大绝对值，单位是底层控制量。I 长期顶到上限时先检查前馈、阻力和动力上限，不直接扩大。 |
| `speed_rate_limit` | 80.0 | 动力每秒最大正常变化量。`rate[steer,speed]` 第二项频繁为 True 且起步太慢时，小幅增加；起步冲击大时减小。 |
| `target_accel_mps2` | 0.20 | 内部速度目标的上升速率。起步过急则降低；`v_ref` 本身上升慢时，增加 P 无法改变这段斜坡。 |
| `target_decel_mps2` | 0.40 | 正速度目标下调时的斜坡速率。需要更快降低请求时可增加，但这不是实车制动减速度；零速/异常停车会绕过正常平滑。 |

例如忽略偏置与 P/I，0.20 m/s 对应前馈幅度 40，0.10 m/s 对应 20；这些值能否让车动起来，要靠实车测量。积分在限幅/变化率受限时可能冻结，这是抗积分饱和机制。

## 4. 方向 PD：区分力度不足和响应太慢

```text
限幅前方向偏移 = steer_sign × (steer_kp × 方向误差 + steer_kd × 滤波后的误差变化率)
最终 steer = steer_center + 限幅、变化率限制后的偏移
```

方向误差单位为 **rad**；D 项是目标方向误差的变化率，不是直接用 IMU 角速度。

| 参数 | 当前值 | 如何调整 |
|---|---:|---|
| `steer_kp` | **3000.0** | 同一误差产生多大的转向偏移。目标正确但实际修正不足、且未受限时，可小步增加；左右摆动/明显过冲则减小。当前值为原内置初值的 10 倍，首次实车需重新确认是否合适。 |
| `steer_kd` | 30.0 | 对误差变化的响应，通常用于抑制过冲。P 基本合适后少量调整；噪声引起频繁抖动时可降低。效果也依赖目标是否平滑。 |
| `steer_derivative_tau_s` | 0.15 | D 项低通时间常数。增大可减少高频噪声，但增加滞后；减小响应更快，也更容易抖。 |
| `steer_rate_limit` | 300.0 | 转向每秒最大正常变化量。`rate` 第一项为 True 且转向建立太慢时，可小步增加；动作过急则减小。与转向幅度上限是两件事。 |
| `steer_jump_reset_deg` | 20.0 | 相邻方向误差突变超过此值时撤去 D 项，避免目标跳变产生尖峰。通常保留，不用它调整日常转弯力度。 |

当前 P 增益下，10° 误差仅 P 项就约产生 **524** 的偏移；约 **11.5°** 即达到 600 限幅（忽略 D）。原 300 增益下，10° 仅约 52。若已饱和，继续增大 P 不会增加可用幅度。

当前变化率 300 单位/s，从中位到 600 至少约需 **2 s**，从 -600 到 +600 至少约需 **4 s**。因此“最大力度够但打过去太慢”应检查 `rate`；“已经顶到允许幅度却仍转不过来”需检查速度、实际转弯半径和路径是否可实现。

## 5. 巡航参考：决定想往哪里走

墙线/中线可靠时，巡航目标大致为：

```text
目标方向 = 走廊航向 + atan2(回中增益 × 横向偏移, 目标点距离)
```

先看紫色中线和 `axis` / `center_left` 是否符合现场，再调控制器。目标本身偏错，增大 PD 只会更积极地追错方向。

| 参数 | 当前值 | 如何调整 |
|---|---:|---|
| `corridor_goal_distance_m` | 1.50 | 巡航回中目标点距离。减小通常回中更急，增大更平缓；先小幅调整，避免与 P 同时改变。它不同于下节的安全检查距离。 |
| `corridor_lateral_gain` | 1.0 | 横向回中强度。航向已经接近走廊方向但长期偏一侧时，可适当增大；左右来回穿过中线则减小。 |
| `corridor_max_lateral_correction_deg` | 20.0 | 仅横向回中部分的修正角上限；限得过小时大偏移恢复慢，但增大前要确认中线与空间可用。 |
| `corridor_max_target_deg` | 45.0 | 巡航允许的总目标角上限；超过会停止，不会把它截断后继续开。大拐角应由转弯行为处理。 |
| `corridor_candidate_tolerance_deg` | 5.0 | 合格安全候选可偏离巡航参考的范围。CRUISE_BLOCKED 时先看净空/未知区，不能仅靠放宽此值转向旁边开口。 |
| `corridor_filter_tau_s` | 0.25 | 墙线/中线模型的时间平滑。模型抖动时适当增大，明显跟不上真实变化时减小；先排除错误拟合。 |
| `corridor_recovery_heading_deg` / `corridor_recovery_offset_m` | 15.0° / 0.25 m | 航向或横向偏移超过门槛时降速。希望更早降速可降低门槛。 |
| `corridor_slow_speed_scale` | 0.50 | 大偏差、单墙、历史保持时的请求速度比例；可降低以留出纠偏时间，通常不靠提高此值解决控制断续。 |

若棕色墙线长期缺失或宽度错误，才检查以下感知参数：

| 参数 | 当前值 | 调整依据 |
|---|---:|---|
| `corridor_min_width_m` / `corridor_max_width_m` | 0.90 / 3.50 m | 合理走廊宽度范围，用卷尺测得墙间宽度核对；不把所有房间开口都纳入。 |
| `corridor_min_span_m` | 1.20 m | 一条墙线需要的真实支持跨度；局部可见墙短时可适度降低，但短障碍/门框更容易被认成墙。 |
| `corridor_min_inliers` | 12 | 网格采样后支持点数下限。确因点稀疏未拟合时才考虑降低。 |
| `corridor_line_tolerance_m` / `corridor_max_rmse_m` | 0.06 / 0.04 m | 内点距离与拟合误差门槛。略增大可容纳噪声，但更容易混入非墙点；结合真实点与墙线图调整。 |

## 6. 车体和雷达：按测量填写

| 参数 | 当前值 | 调整依据 |
|---|---:|---|
| `vehicle_width_m` | 0.22 | 真实车宽，含可能碰撞的突出部分。不要为了让候选通过而缩小。 |
| `front_overhang_m` / `rear_overhang_m` | 0.16 / 0.26 | **雷达中心**到车头/车尾的距离，前后不对称，已取实测上限。 |
| `safety_margin_m` | 0.10 | 真实车体之外的额外裕量。经核对定位、安装、停车和实际净空后才考虑小幅收紧，尺寸本身不变。 |
| `sensor_yaw_offset_deg` | 0.0 | 将雷达扫描旋转到车体轴向的角度，逆时针为正。根据前方固定物在雷达图中的位置核验。 |
| `corridor_sensor_x_m` / `corridor_sensor_y_m` | 0.0 / 0.0 | 雷达相对 **base_link 原点**的平移，前/左为正。当前未知；需先确认里程计原点，不能用雷达到车头的距离直接代填。 |
| `lookahead_m` | 1.50 | 巡航候选的直线车体扫掠要求距离。减小可能提高局部通过率，也缩短提前检查范围；依据速度与实测停车距离调整。 |
| `no_return_distance_m` | 5.0 | +inf 的有限规划深度上限，还受雷达 range_max 限制。不是测出的自由距离；先核对驱动语义，不为追求候选而任意增大。 |

当前巡航用最远车角加裕量的圆盘，半径约 **0.382 m**，比车体真实半宽保守；转弯用加裕量的矩形并额外覆盖采样间隙。两种检查方式不同，窄道不通过时先读阻塞原因。

## 7. 右转：先确认出口，再看跟踪

| 参数 | 当前值 | 如何调整 |
|---|---:|---|
| `turn_enabled` | true | 首次直路调试设 false；需要测试单右转时再开启。 |
| `turn_approach_speed_mps` / `turn_speed_mps` | 0.10 / 0.10 | 接近速度、转弯及出口对齐速度上限，与全局目标取小。转弯反应不够时可先减速，再排查转向响应。 |
| `turn_activate_distance_m` | 3.50 | 入口在接近轴上的前向激活距离上限。适当增大可更早进入低速接近，但前提是已有可信出口线索，不会凭空增加侧向可见性。 |
| `turn_min_radius_m` / `turn_max_radius_m` | 0.70 / 1.20 | 尝试生成的圆角半径范围，优先选可行的较大半径。最小值应符合实测能力；减小规划半径不会让车轮自动转得更多。 |
| `turn_lookahead_m` | 0.65 | 沿锁定路径选择跟踪点的距离，也参与曲率转方向误差。减小通常使纯追踪更局部，但同时改变 PD 收到的误差，实际力度不一定单调变强；小步试验、结合曲率和输出判断。 |
| `turn_check_distance_m` | 0.80 | 每帧至少检查的短弧长度。缩短会降低提前检查范围，不能作为消除 TURN_BLOCKED 的常规办法。 |
| `turn_reaction_time_s` | 0.30 | 停车距离估计中的响应延迟。实测延迟更长就增大。 |
| `turn_braking_decel_mps2` | 0.30 | 停车距离估计中的减速度。实测更弱应减小；增大会算出更短停车距离，不代表实际刹车增强。 |
| `turn_exit_heading_tolerance_deg` / `turn_exit_center_tolerance_m` | 15.0° / 0.30 m | 回归巡航时允许的航向与回中误差。若已稳定对齐却交接慢，核对测量和日志后小幅调整；放宽会更早交接。 |
| `turn_exit_confirm_frames` | 3 | 出口位置、航向和新走廊同时合格的连续帧数，一般保留。完成还要求整车含裕量越过入口。 |

短弧检查长度取 `max(turn_check_distance_m, |速度| × 响应延迟 + 速度² / (2 × 减速度))`。低速时往往由 0.80 m 的下限决定，修改减速度未必会改变当前检查范围。

**出口本身未确认时**，再看以下参数，而不是增加方向 P：

| 参数 | 当前值 | 调整依据 |
|---|---:|---|
| `exit_min_width_m` / `exit_max_width_m` | 1.0 / 3.5 m | 道路入口的可见宽度范围，按现场道路宽度核对；下限过低容易把门洞认成路口。 |
| `exit_probe_depth_m` / `exit_min_depth_visible_ratio` | 1.0 m / 0.15 | 探测纵深和能看到完整纵深的最低入口比例。降低要求会更早确认，也更容易误认；先看实际遮挡和真实边界支持。 |
| `exit_confirm_frames` / `exit_confirm_time_s` | 3 / 0.15 s | 确认需要同时满足的帧数与持续时间，不能替代结构证据。一般先保留。 |

橙色 CORNER_HINT 只允许低速接近观察，不能仅凭持续出现升级成可执行转弯。当前能力是单个右转，左右都有通路时采用课程路线的右侧分支先验。

## 8. 局部恢复：只在正常参考失败后介入

v6 默认启用独立恢复：先停车，确认反馈速度已足够低和安全短弧连续稳定，再以低速修正。沿当前/近期可信道路或已确认出口引导，不向任意空旷侧路盲转；新走廊和安全巡航目标连续确认后交还正常行为。straight/perception 不使用恢复。

| 参数 | 当前值 | 现场如何调整 |
|---|---:|---|
| `recovery_enabled` | true | 设 false 可对比旧的故障锁存方式；初次中位/PD/PI 标定可先关闭。 |
| `recovery_speed_mps` | 0.06 | 局部修正速度上限，与全局目标取小。需核验低速动力死区；不动时看控制输出与实际反馈，不直接提高上限。 |
| `recovery_stop_speed_mps` | 0.05 | 开始修正前允许的最大速度绝对值。反馈仍较快则持续等待，不为让回放产生箭头而放宽。 |
| `recovery_confirm_frames` / `recovery_confirm_time_s` | 3 / 0.20 s | 候选与交接连续确认要求；帧数与时间同时满足。一般保留，抖动明显时先排查输入。 |
| `recovery_check_distance_m` | 0.60 | 每帧至少检查的恢复短弧长度，还会计入停车距离；缩短会减少提前检查范围，先保持。 |
| `recovery_curvature_samples` | 13 | 左右弧线与直行的搜索密度，必须为至少 3 的奇数。增加可能找到更细的路径，但增加计算耗时；先观察输入积压。 |
| `recovery_max_heading_deviation_deg` | 65.0 | 候选末端航向可偏离引导方向的上限。增大会扩大搜索，也更易偏离道路；通常不改。曲率仍受 turn_min_radius_m 限制。 |
| `recovery_guide_timeout_s` / `recovery_guide_travel_m` | 1.0 s / 0.35 m | 无当前真实墙线时，历史走廊引导的年龄/位移上限；任一超限就不再据此运动，不用它补齐长时间丢失。 |
| `recovery_max_input_gap_s` | 1.0 | 消息间隔或真实有效接收间隔超过此值，不允许自动恢复；原 0.5 s 停车检查保持，较短中断也必须重新确认。 |
| `recovery_max_duration_s` / `recovery_max_travel_m` | 20.0 s / 0.80 m | 一组尝试的总时间和累计移动上限，等待不刷新，移动来回也累计。只有测量证明恢复确有进展且空间足够时才考虑调整。 |
| `recovery_max_attempts` / `recovery_normal_reset_time_s` | 3 / 1.0 s | 连续不稳定期间允许进入恢复的次数；正常行为连续稳定后才重置预算，避免无限启停。 |
| `recovery_progress_timeout_s` / `recovery_min_progress_m` | 4.0 s / 0.03 m | 执行修正时，应在指定时间内取得的最小进展。无进展先查动力死区、打滑或错误目标，不直接延长。 |

日志可同时出现原转弯 `TURN_FAULT` 和 `recovery=MOVE/OK`，表示软路径问题已交由恢复接管；实际执行看节点是否 OK。`RECOVERY_COMPLETE` 当帧仍停止，然后正常控制重新预热。已选右出口必须确认新道路方向和整车越过入口，不能因为前方仍通而改成直行。

尚无可信引导，或未执行修正前引导已过期时，`RECOVERY_UNAVAILABLE` 不接管，保留原行为等待，不会凭纯空旷区域强行转向。

`RECOVERY_NO_GUIDE`、`RECOVERY_BLOCKED` 继续等待；预算/进展不足的 `RECOVERY_FAULT`、位姿重建/时间回跳等硬故障仍需人工检查后重启。回放不会响应停车，持续高反馈速度或继续位移可能使恢复一直等待或预算耗尽；这不能直接判断实车恢复效果。

## 9. 遇到这些状态，先排查而非加增益

先读控制日志中的这些量：

| 日志字段 | 怎么看 |
|---|---|
| `requested` / `v_ref` / `v_used` | 上层请求速度 / 斜坡后的内部目标速度 / 本次使用的里程计速度，单位均为 m/s。 |
| `steer[P,D]` / `speed[FF,P,I]` | 各控制项的贡献；能区分是参考/前馈不合适，还是 P/I/D 在补偿。 |
| `sat[steer,speed]` | 转向、动力的原始计算是否超出幅度范围；True 时先查限幅原因。动力原始值小于 0 也算饱和，不只指动力过大。 |
| `rate[steer,speed]` | 转向、动力是否被每秒变化率限制；顺序同上。 |
| `I_frozen` / `D_reset` | 因输出受限冻结积分 / 因误差跳变或参考切换撤去微分，一般是保护逻辑正常工作。 |

| 现象/日志 | 优先检查 |
|---|---|
| `WAITING` / `WAITING_ODOM` | 传感器、同步、独立里程计节点及话题。 |
| `UNALIGNED_ODOM` / `STALE_ODOM` | 时钟、消息时间、实际接收及 `skew`；实车 use_sim_time=false，回放 true 并发布 --clock。 |
| `CORRIDOR_ACQUIRING` / `CORRIDOR_LOST` | 真实墙线、拟合支持、宽度与 scan_dt；不一定是通道真的堵塞。 |
| `CRUISE_BLOCKED` / `TURN_BLOCKED` | 当前参考的车体扫掠、真实障碍和未知区。后者保留原路径停车等待。 |
| `TURN_NO_PATH` | 已确认出口暂时没有可接入的圆角，核对位置、空间和实际半径能力。 |
| `TURN_FAULT` | 结合 recovery 看是否为可恢复路径问题；硬转弯故障继续停车。记录首次原因，不能仅依据原转弯状态判断最终控制。 |
| `RECOVERY_FAULT` | 恢复预算、进展或输入连续性不满足；锁存停车，保留 cause/reason，人工检查后重启。 |
| `CONTROL_WARMUP` | 有效输入恢复后等待一帧建立时间差；持续反复出现才查上游为何反复失效。 |
| `OK`、有目标，但 speed 为停止值 | 查看 v_ref/v_used 与 FF/P/I。回放中实测速度可能高于本次目标；控制输出不能改变录制输入，不能据此标定实车 PI。 |

通常保留 `odom_scan_tolerance_s=0.15`、`odom_timeout_s=0.5`、`control_max_dt_s=0.5`、`corridor_max_update_gap_s=0.5`、`turn_max_update_gap_s=0.5`。不要用放宽门槛掩盖输入积压/丢帧。

`min_scan_finite_ratio=0.05`、分箱覆盖和插值上限属于数据可用性门控；不要为增加青色箭头而随意降低。`turn_max_tracking_error_m=0.55`、`turn_max_duration_s=60`、`turn_max_travel_m=7` 是故障保护，不是指定路线的距离和转弯时间。

## 10. 现场至少记下什么

- 每次配置版本、改动项、电量、目标速度、实际速度、直行偏差和是否过冲。
- 雷达相对 base_link 的实际位置；走廊/入口宽度；已有车体尺寸是否覆盖全部突出部分。
- 多个低速稳态下的 `[FF,P,I]` 和底层动力输出，起步死区；前移已知距离时 odom 的对应距离。
- 固定速度/转向下的实际转弯半径、响应延迟，尽量用与 base_link 一致的轨迹参考点；实际转动 90°时 odom 的角度。
- 从低速发送停止值到完全停下的距离与延迟，用于核对安全检查。内部目标速度下降不等于车已减速。
- 出错时保留状态、首次原因和相关录制，不只保留没有箭头的截图。

## 补充：改好参数怎么生效

参数启动时读取，修改文件后必须重启。两种方式任选一种；完整步骤见 [MIGRATION.md](MIGRATION.md#4-修改参数或代码后怎么重新运行)。以下均假定当前终端已加载 ROS 和工作区环境。

**保持最短启动命令**：修改源码 YAML 后重新构建，确保安装配置更新。

```bash
cd ~/ros2_ws
colcon build --packages-select process_node --symlink-install
source install/setup.bash
ros2 launch process_node process_node.launch.py
```

**只改 YAML、跳过构建**：在工作区根目录明确加载源码配置。

```bash
cd ~/ros2_ws
ros2 launch process_node process_node.launch.py config:=src/process_node/config/baseline.yaml
```

离线回放在启动命令后加 `use_sim_time:=true`，另一个终端 `ros2 bag play … --clock`；实车不加。launch 中图形显示由启动参数 `show_visualization` 覆盖；要关闭窗口请加 `show_visualization:=false`。

怀疑加载了旧参数时，另开已加载环境的终端检查实际值，例如：

```bash
ros2 param get /process_node/process_node steer_kp
```
